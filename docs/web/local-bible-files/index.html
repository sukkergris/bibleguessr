Feature

Bring your own Bible file

Client-side parsing of EPUB/RTF Bible exports, entirely in the browser — for translations the backend can't legally redistribute.

Why this exists

Some translations (e.g. Jehovah's Witnesses' Ny Verden-Oversættelsen/NWT) can't be legally served from a shared backend. Instead, the player supplies their own exported file; it's parsed and used entirely in their own browser and never uploaded anywhere. This is why the backend only ever ships one public-domain translation (bibles/bibelen-dk) — anything else has to come through this path.

Two supported export formats

EPUB — frontend/src/epub-parser.ts

Targets "JW Library" family EPUB exports (a zip archive; fflate's unzip pulls out the .xhtml chapter entries, skipping images).

  • A chapter page is recognized by a nav header regex matching book name and (optional) chapter number.
  • Verse boundaries come from <span id="chapter{N}_verse{M}"></span> markers — not the rendered verse-number label, because verse 1 of a chapter renders the chapter number as a drop cap, not "1". The marker id is the only reliable source.
  • Strips the rendered number label and inline footnote markers, decodes HTML entities, collapses whitespace.
  • Processes chapter files in batches of 50, yielding to the main thread between batches (requestIdleCallback, falling back to setTimeout) so a multi-MB file doesn't freeze the page.

detectEpubTranslationName(file) reads content.opf's <dc:title>/<dc:language> metadata for a real display name (e.g. "Ny Verden-Oversættelsen (nwt-D) (da)") rather than the filename — JW Library exports are often all named identically regardless of language, so the filename alone can't tell two cached translations apart.

RTF — frontend/src/rtf-parser.ts

Targets "Bible Online Download" RTF exports: a zip with one .rtf file per book.

  • Book name and chapter headings extracted via regex on specific RTF font/style groups.
  • Verse markers recognized by a distinct RTF font selector (body text uses a different one) — the same "the verse number is styled differently from the text" idea as the EPUB parser's drop-cap detection, just expressed through RTF fonts instead of HTML.
  • Single-chapter books (Obadiah, Philemon) have no chapter heading; all their verses default to chapter 1.
  • Handles \uNNNN? Unicode escapes and strips RTF control words.
  • Processes in batches of 5 books (smaller than EPUB's 50 — each RTF book file is much larger than one EPUB chapter fragment).
Known data-quality issue, left as-is

About 5 of ~1,180 chapters have a mis-exported verse-number marker in the source data itself (e.g. Judges 17:2), causing that verse's text to bleed into the previous one. This isn't a parser bug — it's inherited from the export — and is documented in the file rather than worked around.

Both parsers share a comment convention: bump PARSER_VERSION in verse-cache.ts if their regexes ever change, so stale cached parses get invalidated automatically.

Caching — frontend/src/verse-cache.ts

Caches the parsed Verse[] result in IndexedDB (database bibleguessr, store local-bible-cache) — not the raw file. Browsers don't allow silently re-reading a File across sessions without a new user gesture, so a returning visit can skip re-parsing, but never skips the file picker itself.

  • fingerprintFile(file) — key format name:size:lastModified, cheap to compute without hashing the whole file, and doubles as the storage key so re-uploading the same file overwrites rather than duplicates.
  • Multi-entry by design: listCache() returns every cached translation, newest first — a player can have several cached files (different languages, EPUB and RTF both) and pick between them, rather than only ever having the most recent upload available.
  • writeCache(fingerprint, translation, verses), deleteCacheEntry(fingerprint).
  • Entries from a stale PARSER_VERSION are filtered out as if absent, never silently served.

Wiring — frontend/src/components/game-setup.ts

  1. Toggle between Mode = 'server' | 'file'. On mount, listCache() populates a list of previously-cached files, shown instead of a raw dropzone if any exist.
  2. File picker accepts .epub,.zip via a hidden input or drag-and-drop.
  3. On a new file: validates the extension, lazily import()s the matching parser module.
  4. Derives a translation name (EPUB metadata, or filename minus extension as fallback), parses with progress callbacks, writes the result to the cache.
  5. Wraps the parsed verses via createLocalVerseSource(verses) (local-verses.ts) into a VerseSource — the same interface the backend-backed api object implements, so bg-app.ts treats either source identically regardless of where the verses came from.

Verify it

  • frontend/src/local-verses.test.ts covers createLocalVerseSource's filtering/sorting/dedup behavior.
  • Coverage gap: there are no dedicated unit tests for epub-parser.ts, rtf-parser.ts, or verse-cache.ts despite their parsing complexity — worth adding if you're touching those files.
  • Manual: upload a real EPUB/RTF export, confirm the parsed book/chapter/verse counts look right and the translation name displays sensibly, then reload the page and confirm it appears in the cached-file list without re-parsing.
