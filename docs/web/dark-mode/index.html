Feature

Dark mode

Light, Dark, or follow the system — applied through one set of semantic tokens rather than per-component overrides.

One contract, not twenty

Colours are defined once as semantic tokens on :root in frontend/src/index.css and inherited into every Lit shadow root, because CSS custom properties cross shadow boundaries. That is what makes a single theme contract possible.

Tokens are named for meaning, not appearance — --surface, not --white — so a component asking for a surface gets the right one in either theme without knowing which theme is active.

The migration replaced 89 hard-coded colour literals across 20 components and removed every per-component prefers-color-scheme block. Those blocks were not merely redundant: they key off the operating system, so they would have overridden an explicit Light choice on a dark machine.

Choosing a theme

The control lives in the Nerd Panel under Appearance, as native radio inputs rather than buttons with aria-pressed: a theme is one choice among three, which is what a radio group means, and native semantics give arrow-key navigation and correct announcement for free.

Only the preference is stored, under a versioned bibleguessr: key. An unrecognised, corrupt or unreadable value falls back to following the system rather than leaving the application unstyled. Changing theme does not touch game, chat, setup, report or cached-file state.

No flash of the wrong theme

The theme is applied in frontend/src/main.ts before the app renders. The prefers-color-scheme block in the stylesheet covers the first paint before that runs, and is guarded with :not([data-theme='light']) so it can never beat an explicit choice.

color-scheme is set alongside data-theme, so browser-rendered UI — form controls, scrollbars — matches rather than staying stubbornly light. While the preference is System, the app keeps listening for OS changes and repaints; an explicit choice deliberately stops listening.

Implementation

frontend/src/theme.ts holds the preference, its validation and the apply logic; frontend/src/components/theme-select.ts is the control. Preference validation is unit tested in frontend/src/theme.test.ts; default/system behaviour, persistence, corrupt storage, real rendered colours inside shadow roots, keyboard operation and state preservation are covered by frontend/e2e/theme.spec.ts.
