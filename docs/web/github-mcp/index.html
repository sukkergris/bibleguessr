GitHub MCP setup

How to connect a local coding agent to GitHub through MCP so it can read repository data and issues without giving the agent direct access to your token value.

Secret handling

Never paste a personal access token into chat, source files, shell history, docs, screenshots, or issue comments. Configure it only in your local MCP or VS Code secret storage.

1. Create a fine-grained token

  1. Open GitHub's fine-grained personal access token settings.
  2. Limit the token to the repositories the MCP server should access, such as sukkergris/bibleguessr .
  3. Grant the smallest permissions needed. For read-only issue and repository inspection, use read permissions only. Add write permissions only when the workflow truly needs to create or update GitHub data.
  4. Set an expiration date and rotate the token when it expires or if it may have been exposed.

2. Configure the GitHub MCP server

Add the GitHub MCP server to your local MCP configuration using the token as a secret or environment value. The exact file and UI depend on the MCP client you use, but the important rule is the same: the token belongs in local secret configuration, not in this repository. 

{
  "servers": {
    "github": {
      "command": "github-mcp-server",
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "stored outside the repo"
      }
    }
  }
}

Treat the snippet as shape only. Do not commit a real token or a machine-specific MCP config file unless the token value is omitted and the file is intentionally safe to share.

3. Verify access

Ask the coding agent to perform a harmless read-only check through GitHub MCP, such as fetching this repository's README.md or reading a known issue number. A successful read proves the MCP server is configured for that operation; it does not reveal which token was used or what the token value is.

4. Keep the permissions narrow

  • Prefer repository-scoped tokens over account-wide tokens.
  • Prefer read-only permissions unless write access is required.
  • Use separate tokens for local experiments, automation, and production workflows.
  • Revoke unused tokens and rotate any token that may have been copied into an unsafe place.
  • Review the MCP tools exposed to the agent; the available tools define what the agent can do.

What the agent can see

The agent can use only the GitHub MCP tools exposed by the current VS Code session. It can see whether an MCP operation succeeds and can see the data returned by that operation. It should not be able to see the token value itself unless the environment is misconfigured to expose secrets as normal files, logs, or chat text.

Troubleshooting

Symptom Check
MCP cannot read the repository. Confirm the token is scoped to the repository and has metadata/content read access.
MCP can read files but cannot read issues. Confirm the token has issue read permission and the issue belongs to the configured repository.
The agent cannot create or update GitHub data. Check whether write tools are exposed and whether the token has the matching write permission.
You are unsure how much access exists. List the exposed MCP tools and test only harmless read operations before enabling write access.
