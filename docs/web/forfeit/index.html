Feature

Forfeit confirmation

Leaving an active multiplayer game requires an explicit, accessible confirmation instead of the browser's built-in prompt.

User flow

  1. The player selects Forfeit below the active round.
  2. An in-app dialog explains that forfeiting ends the current game and focuses Cancel by default.
  3. The player can cancel, press Escape, click the backdrop, or explicitly confirm the forfeit.
  4. While the request is in flight, both actions are disabled so the server receives at most one submission.
  5. If the request fails, the dialog stays open and announces a retryable error.

Accessibility behavior

The dialog uses role="dialog", aria-modal="true", and labelled/described content for screen readers. Cancel is the initial focus target because it is the safe default.

Tab and Shift+Tab cycle between enabled dialog actions. Escape and the two non-confirmation dismissal paths return focus to the original Forfeit button, so keyboard users do not lose their place in the round view. A failed request is exposed with role="alert" and leaves the confirmation action available for retry.

Implementation

frontend/src/components/multiplayer-game.ts owns the dialog state, focus lifecycle, keyboard handling, error display, and request submission. The existing forfeitGame() SignalR call remains unchanged; successful completion is still delivered through the server-authoritative GameOver event.

The behavior is covered by the forfeit scenario in frontend/e2e/multiplayer-round.spec.ts, including focus placement, focus wrapping, Escape, Cancel, backdrop dismissal, and the successful server round-trip.
