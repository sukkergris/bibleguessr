Feature

Remembered Bible

The player chooses their Bible once — a server translation or one of their own uploaded files — and every setup screen starts on it, until they choose another. It survives closing the browser.

One choice for every screen

There is one Bible choice, not one per game type. Every setup screen preselects it: singleplayer for each game type (The Bible, Books, Chapters), the multiplayer room setup, and the daily quiz. Choosing another Bible on any of them changes it for all of them — including on "Play again" and on a new visit.

All of them use the same picker, <bg-translation-source-select> (see Local Bible files). Singleplayer used to have its own copy of it; that copy is gone, so the remembering, the file announcements and the accessible file input exist in one place only.

What is stored

Only which Bible: { kind: 'server', translation } or { kind: 'file', fingerprint }, where the fingerprint is the uploaded file's cache key (name, size, last modified — see Local Bible files). It is kept in this browser's local storage under bibleguessr:preferences:bibleChoice:v1. Never verse text, and never sent anywhere: a fingerprint holds the file's name. In multiplayer each player already plays from their own Bible; the choice only preselects this player's own picker, and only book, chapter and verse numbers travel, as before.

Only the player's own actions are remembered: picking a translation, switching to the server tab, choosing a cached file or uploading one. The picker's automatic preselection of the first translation is not.

Validation and fallbacks

Every read is validated, like the remembered setup choices. A missing, malformed or outdated value is simply no choice, and the picker behaves as it always did — the first server translation:

  • A remembered translation the server no longer offers: the first translation.
  • A remembered file that is no longer cached (removed, or parsed by an older parser — see PARSER_VERSION): the first translation.
  • Storage unavailable, as in private browsing: nothing is remembered.
  • A remembered file is restored from the local cache alone, so it works with the server unreachable. A remembered server translation with the server unreachable shows the usual error — the picker never switches to a file on the player's behalf.

The translation list (from the server) and the file cache (local) arrive independently. Restoring is abandoned the moment the player makes a choice of their own, so a late answer never overrides it.

Game-type selections follow their Bible

The books or chapters picked for a game type are kept for the session in bg-app.ts's savedChoices. They name books in one Bible's own spelling, so each is kept with the Bible it was made against and only restored for that Bible. With a different Bible the selection starts fresh; switching back brings it back.

Accessibility

  • A preselected server translation moves no focus and announces nothing: the select shows it and exposes it to assistive technology.
  • A restored file is announced once through the picker's file status region: "Using file name from last time."
  • The mode tabs' aria-selected follows the restored mode.
  • Changing the Bible stays fully keyboard-operable.

Implementation and tests

frontend/src/bible-sources/bible-choice-storage.ts holds the BibleChoice type, the storage key, and the pure parsing and fallback rules (parseBibleChoice, translationToPreselect, fileToRestore), unit tested in bible-choice-storage.test.ts. The picker in translation-source-select.ts loads and saves it. frontend/src/components/game-setup.ts keys the game-type selection by Bible.

frontend/e2e/remembered-bible.spec.ts uploads a file in one game type and finds it preselected in another, in multiplayer, in the daily quiz, after a reload and on "Play again", with nothing about it sent to the server. It also covers the fallbacks and that a Books selection only comes back with its own Bible.
