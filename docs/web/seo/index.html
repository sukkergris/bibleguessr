Feature

Search engines

The basics that let search engines find, understand and list BibleGuessr's pages: robots.txt, a sitemap, and a title, description and canonical address for every page.

What is in place

Piece Where What it does
/robots.txt frontend/public/robots.txt Lets crawlers in everywhere except /admin/ and /cdn-cgi/, and names the sitemap. /api/ is deliberately not blocked: the app fetches it to build each page, and Google builds pages the way a browser does.
/sitemap.xml frontend/public/sitemap.xml Every page search engines should know about: the front page, each game type, Multiplayer, Social and the daily quiz. No lastmod: a static file can't know when a page changed, and a wrong date is worse than none.
Each page's <head> frontend/src/routing/page-meta.ts, page-head.ts The title, a description of its own, and a canonical link to its address on the public site — or, for a room's pages (/multiplayer/<code>, /watch/<code>), which only exist as long as the room, noindex and no canonical link.
Link previews frontend/index.html A description and Open Graph tags for readers that don't run the app: chat apps and social networks building a preview of a shared link. They describe the site as a whole.

One public address

Canonical links always point at https://bibleguessr.uk — SITE_URL in page-meta.ts — whichever host served the page, so a copy on another host (www, a test server, the local replica) points search engines at the real one. robots.txt and sitemap.xml are static files and can't import it, so page-meta.test.ts checks that they, and the description in index.html, agree with the code. Changing the domain means changing all of them; the test says which.

Pages built by the app

The server sends the same index.html for every address, and the app builds the page — including its head — in the browser (see Links and navigation). Google runs the app before indexing, so it sees each page's own title, description and canonical link. Following Google's advice for tags added by JavaScript, the app keeps exactly one canonical link and one description however often the page changes, and index.html itself has no canonical link that could contradict it.

Readers that don't run JavaScript — link previews in chat apps, some smaller search engines — only ever see index.html's site-wide tags.

Serving the files

Vite serves frontend/public at the site root in development and copies it into the build. In the nginx image, server-replica/nginx/includes/static-assets.conf serves /robots.txt and /sitemap.xml from the built files, the sitemap with Cache-Control: no-cache so a new page list is picked up at once. (The nginx template used to send /sitemap.xml to the backend, which has never served one.)

Adding a page

  1. Give it an address — see Links and navigation.
  2. Give it a title and description in pageMetaOf; the compiler points there.
  3. If search engines should list it, add it to INDEXABLE_ROUTES and a <url> to sitemap.xml — page-meta.test.ts fails until both agree.

After deploying

  • Make sure production answers every app address with index.html (see Links and navigation) — otherwise crawlers get 404s for every page in the sitemap but the front page.
  • Verify the site in Google Search Console and Bing Webmaster Tools, and submit https://bibleguessr.uk/sitemap.xml. frontend/public/BingSiteAuth.xml still holds a placeholder instead of Bing's verification code.

Not done yet

  • A preview image. Shared links show no picture; that takes an og:image of about 1200×630 pixels.
  • Previews per page. A shared daily quiz link previews as the site as a whole, because preview readers don't run the app. Page-specific previews need the server to put each page's tags in the HTML it sends (prerendering; the nginx config has unused prerender hooks from its template).
  • Structured data (JSON-LD), e.g. describing the site and the game.
  • The page's language. index.html says lang="da" while the interface is English. The bundled Bible's verses are Danish, though, and screen readers choose their voice from lang, so changing it needs the verse text marked with its own language at the same time.
  • One host. If both www.bibleguessr.uk and bibleguessr.uk serve the site, the canonical links keep search results together, but a redirect to one host is cleaner.

Tests

  • frontend/src/routing/page-meta.test.ts — titles, descriptions, which pages are listed, canonical addresses, and that robots.txt, sitemap.xml and index.html agree with the code.
  • frontend/e2e/seo.spec.ts — each page's head as the app leaves it, rooms kept out of search results, every sitemap page opening as itself, and robots.txt.
