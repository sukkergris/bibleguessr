Feature

Remembered setup choices

The round count and per-verse time limit are remembered per browser, so returning to setup does not mean recreating the same preferences every time.

What is remembered

Only two numbers: the selected round count, and the selected time limit. They are preferences for creating a game, stored locally under the application's bibleguessr: namespace with versioned keys. Nothing is uploaded merely because it is remembered.

They are not the settings of a game already running. Once a game starts, its own session fixes those values, so changing a preference afterwards cannot affect a game in progress — and a challenged player sees the values carried by the request, never the challenger's storage.

Validation

Stored values are untrusted: they can be hand-edited, left over from an older version, or corrupt. Every read is validated, and anything unusable is replaced by the default rather than allowed to break setup — round count falls back to 5 outside 3–10, and the time limit falls back to unlimited outside 2–60 seconds.

Unlimited is written as 0 at the storage boundary and read back as the undefined/Unlimited the UI and domain already use. A stored one-second round is rejected rather than clamped: the slider's 1 notch is clamped up to 2 before saving, so such a value should never exist, and trusting it would preserve the bug that wrote it.

Reads and writes tolerate storage being unavailable or denied, as in private browsing. Setup continues with in-memory defaults and the controls still work; the choice simply is not remembered.

Implementation

frontend/src/game-preferences.ts holds the keys, defaults, ranges and the pure parsing functions. frontend/src/components/game-setup.ts and frontend/src/components/challenge-settings.ts load on construction and save on change, so a keyboard change persists exactly like a pointer one.

Validation is unit tested in frontend/src/game-preferences.test.ts; the round trip through the real controls, the clamped one-second case, and recovery from corrupt storage are covered by frontend/e2e/game-preferences.spec.ts.
