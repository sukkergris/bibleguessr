Feature

Scoring

How many points a guess earns — book, chapter, and verse number each gated on the level before it also being correct, by each game type's own rule, the same in singleplayer and multiplayer.

Each game type owns its scoring — the same in both modes

Every game type (The Bible, Books, Chapters) has its own scoring rule, and multiplayer scores a guess exactly like singleplayer does. The rule lives in the game type's own module on each side — singleplayer in scoreGuess in frontend/src/game-types/<type>/, multiplayer in scoreGuess in backend/Domain/GameTypes/<Type>.fs — and both are held to one specification per game type: scoring-scenarios/<game type>.json. See Game types.

The rule: tiers, gated, and what's given earns nothing

A guess has three parts — book, chapter, verse number — and each part only counts when every part before it is right too: the right numbers in the wrong book count for nothing, and a part that wasn't guessed isn't right. The standard tiers are book 10, chapter +100, verse number +1000. A game type chooses its own tiers, and what is given at setup is no achievement, so it earns nothing.

  • "One" means one distinct book or chapter: a chapter listed twice is still one chapter, on both sides.
  • What's given is also given in the guess form: the fixed book, a lone chapter and a lone book are selected from the start, so the first part that earns anything can be picked straight away.
  • Book matching ignores case and surrounding whitespace. In multiplayer the book is matched by its number whenever the guess has one, since the two players may read different Bibles that spell it differently (see Multiplayer round sync).
  • The daily quiz draws from the whole Bible, so it scores by the standard tiers (see Daily quiz).

Multiplayer: the same points, and time doesn't change them

The server scores each multiplayer guess with GameType.scoreGuess, which dispatches to the game type's own module, from GameSession.scoreRound. A guess is worth the same as in singleplayer whenever it came in: a round's time limit only ends the round, and a player who didn't guess in time gets no result for it ("Choked!", 0). A result's Correct means the guess earned points — the same "correct" the singleplayer feedback shows.

The results screen counts out of the game type's own maximum

The singleplayer results show total / max, where max is the number of verses times the most one verse can earn in the game played — GameTypeDefinition.maxPoints, reached through registry.ts's maxPointsOf. A perfect game always shows the two numbers equal. The app shell never assumes the standard tiers.

Changing a rule

One game type at a time: edit that type's scenario file (scoring-scenarios/<game type>.json), its frontend definition and its backend module — nothing else. Each scenario case names a selection (as the player's own setup holds it, and as the wire value sent to the server), a guess against the file's verse, and the points it earns in each mode (points.singleplayer, points.multiplayer). Today both modes agree; if one mode is to score differently, change only that mode's points and that mode's module. Each selection also states its maxPoints.

Sharing a result

Both singleplayer's results and the daily quiz have a Share result button, and both write the shared text the same way — frontend/src/shared-kernel/result-sharing.ts's composeShareText: 

BibleGuessr · Books
1120 points
Book · Chapter · Verse
✅ ✅ ✅ 1110
✅ ❌ ❌ 10
❌ ❌ ❌ 0
Played 2026-10-01 14:32 UTC
https://www.bibleguessr.single/
  • A heading (the game type, or the daily quiz and its date), the total, then a line per verse: ✅ (green check) for each part guessed right, ❌ (red cross) otherwise, and that verse's points.
  • The marks come from correctParts, not from the points. Each game type says which columns its shares show (GameTypeDefinition.sharedColumns): The Bible all three; Books and Chapters leave out what is given — a lone picked book, Chapters' fixed book, and a lone picked chapter — since it would always be ✅. So a one-book Books result is headed Chapter · Verse and a one-chapter Chapters result just Verse.
  • "Played …" with date and time in UTC, and — always last — a link to the game: the address it is served from (window.location.origin), so it follows the environment. No share can leave the link out: composeShareText always adds it.
  • No verses and no verse text: a share mustn't give answers away, and verse text never leaves the device.
  • frontend/src/shared-ui/share-or-copy.ts opens the device's share menu where there is one and copies to the clipboard otherwise, for both buttons. It shares the text only, with no separate title: some apps (Slack, for one) show the title in front of the text, which would repeat the "BibleGuessr" the text already starts with.

Verify it

  • frontend/src/game-types/scoring-scenarios.test.ts — every scenario's singleplayer points and maxPoints through the registry, that a perfect guess earns exactly the maximum, and that each selection is sent as its wire. Run via task frontend:test.
  • backend/Tests/GameTypeScoringTests.fs — every scenario's multiplayer points through GameType.scoreGuess, reading the wire exactly as the hub does, and the "nothing picked plays as The Bible" rule. Run via task dotnet:test.
  • The building blocks: frontend/src/shared-kernel/scoring.test.ts, backend/Tests/ScoringTests.fs and, for matching by book number, backend/Tests/MultiplayerScoringByNumberTests.fs. backend/Tests/GameSessionTests.fs checks that a round is scored by the session's own game type, and that time doesn't change the points.
  • End to end: frontend/e2e/game-type-scores.spec.ts — the results screen's maximum per game type, a perfect game, a lone picked book, multiplayer points, and that the room sends the game type it shows.
