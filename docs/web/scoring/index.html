Feature

Scoring

How many points a guess earns — book, chapter, and verse number each gated on the level before it also being correct.

The tiers

Guessed correctly Points Requires
Book 10 —
+ Chapter +100 book also correct
+ Verse number +1000 book and chapter also correct

All three correct: 1110 total. Book matching is case-insensitive throughout.

Mirrored by hand, backend and frontend

This exact tiered logic is implemented twice — once in F#, once in TypeScript — and deliberately kept in sync by hand rather than shared via codegen, matching this project's existing convention for small, rarely-changing shapes (see frontend/src/types.ts's header comment).

Used by domain logic, tested directly bg-app.ts's _onGuessSubmitted — this is what actually drives singleplayer scoring

scoreGuess was extracted out of bg-app.ts (it used to be a private method there) specifically so it's directly unit-testable without instantiating the Lit element, and so it can sit as a standalone sibling next to the backend's version for easy side-by-side comparison.

A second, unused scorer

Scoring.pointsForGuess (time-decaying: full points minus a penalty proportional to how much of the round's time elapsed) and Scoring.isCorrectGuess also exist in Game.fs, but nothing calls either of them today. They're reserved for a future multiplayer round-timer feature — see Multiplayer rooms's "not built yet" section. Don't confuse them with pointsForVerseGuess, which is the one actually in use.

Verify it

Both sides assert the identical scenarios (wrong book → 0; right book, wrong or missing chapter → 10; right book+chapter, wrong or missing verse → 110; all three correct → 1110; case-insensitivity) so a change to one side that isn't mirrored on the other should show up as an obvious asymmetry between the two test files.

  • frontend/src/scoring.test.ts — run via task frontend:test.
