Feature

Scoring

How many points a guess earns — book, chapter, and verse number each gated on the level before it also being correct.

Each game type owns its scoring

The rules on this page are the standard rules. Every game type (The Bible, Books, Chapters) chooses its own scoring rule — singleplayer in its scoreGuess in frontend/src/game-types/<type>/, multiplayer in its scoreGuess in backend/Domain/GameTypes/<Type>.fs. The Bible and Books use the standard rules below; Chapters has its own (next section). Giving one type its own rule is a change in that type's file only; the other types are unaffected. See Game types.

Chapters: what's given earns nothing

In a Chapters game the book is fixed at setup, so getting it "right" is no achievement and earns nothing. The same goes for the chapter when only one was picked: then it's just as given.

  • Singleplayer: the shared kernel's tieredPoints with CHAPTERS_TIERS / LONE_CHAPTER_TIERS in frontend/src/game-types/chapters/chapters.ts.
  • Multiplayer: the standard rule counts a book-only guess as correct. In Chapters a guess is only correct if the chapter is guessed and right — and, with one chapter picked, the verse number too — and then scores like the standard rule (backend/Domain/GameTypes/Chapters.fs).
  • With one chapter picked, the guess form selects it from the start (like the fixed book), so the verse can be picked straight away.

Mirrored by hand, backend and frontend

This exact tiered logic is implemented twice — once in F#, once in TypeScript — and deliberately kept in sync by hand rather than shared via codegen, matching this project's existing convention for small, rarely-changing shapes (see frontend/src/types.ts's header comment).

A second scorer, for multiplayer specifically

Scoring.pointsForGuess (time-decaying: full points minus a penalty proportional to how much of the round's time elapsed) and Scoring.isCorrectGuess (book-number-aware, not name-based — see below) also exist in Scoring.fs, combined into Scoring.standardMultiplayer (untimed rounds: a flat unlimitedCorrectPoints) — this is the standard multiplayer rule each game type's scoreGuess chooses today, applied by GameSession.scoreRound via GameType.scoreGuess. See Multiplayer round sync for the full multiplayer scoring/timer picture. This page's pointsForVerseGuess/standardSingleplayerPoints pair is the singleplayer scorer — the two are deliberately separate (multiplayer never recomputes points locally, and singleplayer has no timer to decay against), don't confuse one for the other.

Sharing a result

Both singleplayer's results and the daily quiz have a Share result button, and both write the shared text the same way — frontend/src/shared-kernel/result-sharing.ts's composeShareText: 

BibleGuessr · Books
1120 points
Book · Chapter · Verse
✅ ✅ ✅ 1110
✅ ❌ ❌ 10
❌ ❌ ❌ 0
Played 2026-10-01 14:32 UTC
https://www.bibleguessr.single/
  • A heading (the game type, or the daily quiz and its date), the total, then a line per verse: ✅ (green check) for each part guessed right, ❌ (red cross) otherwise, and that verse's points.
  • The marks come from correctParts, not from the points. Each game type says which columns its shares show (GameTypeDefinition.sharedColumns): The Bible and Books all three; Chapters leaves out what is given — the book, and the chapter too when only one was picked — since it would always be ✅. So a one-chapter Chapters result is headed just Verse.
  • "Played …" with date and time in UTC, and — always last — a link to the game: the address it is served from (window.location.origin), so it follows the environment. No share can leave the link out: composeShareText always adds it.
  • No verses and no verse text: a share mustn't give answers away, and verse text never leaves the device.
  • frontend/src/shared-ui/share-or-copy.ts opens the device's share menu where there is one and copies to the clipboard otherwise, for both buttons. It shares the text only, with no separate title: some apps (Slack, for one) show the title in front of the text, which would repeat the "BibleGuessr" the text already starts with.

Verify it

Both sides assert the identical scenarios (wrong book → 0; right book, wrong or missing chapter → 10; right book+chapter, wrong or missing verse → 110; all three correct → 1110; case-insensitivity) so a change to one side that isn't mirrored on the other should show up as an obvious asymmetry between the two test files.

  • backend/Tests/ScoringTests.fs — run via task dotnet:test.
  • frontend/src/shared-kernel/scoring.test.ts — run via task frontend:test.
  • Per game type: backend/Tests/GameTypeScoringTests.fs and each frontend/src/game-types/<type>/<type>.test.ts pin down which rule each type uses; frontend/src/game-types/registry.test.ts checks a game is scored by its own type only.
