Developer documentation

How each feature works, under the hood — for anyone picking this codebase up. Each page covers what the feature does, how it's built (backend + frontend), and how to verify it.

Scope

This documents the multiplayer/chat system and its supporting infrastructure as of the current codebase. Singleplayer's core loop (verse card, guess form, server-side verse serving) is straightforward enough that it isn't covered separately — see frontend/src/components/bg-app.ts for the overall phase flow, which every page below links back to.

Features

Multiplayer rooms & chat

Room codes, World chat, the SignalR hub, and the join/roster/chat protocol everything else builds on.

Start a game from chat

Choosing a game type and clicking a player's name to challenge them — send, see, accept, deny, withdraw, REPLACE semantics.

Player presence

Connection-status dots, the 5-minute stale-player sweep, and remembering your name per browser.

Bring your own Bible file

Client-side EPUB/RTF parsing for translations the backend can't legally redistribute, plus caching.

Scoring

The book/chapter/verse point tiers, mirrored by hand between the F# backend and the TS frontend.

Testing

What's covered (xUnit, Vitest, Playwright), what isn't, and exactly how to run all of it.

Not built yet

A few things are visibly scaffolded in the domain/hub but not wired up to anything — worth knowing about so you don't go looking for a caller that doesn't exist:

  • Multiplayer round sync. RoundState, RoundStarted/RoundScored events, and Scoring.pointsForGuess (a time-decaying scorer, distinct from the book/chapter/verse tiers actually in use) are declared but no hub method touches Room.Round yet. See Multiplayer rooms.
  • Actually starting a game from an accepted challenge. Send/see/accept/deny/withdraw are all implemented, and a request now carries the challenger's chosen game type — but accepting only resolves the request; it doesn't start a synced round, since that depends on round sync, which doesn't exist yet. See Start a game from chat.
  • Reconnecting to the same identity. A dropped-then-restored connection always mints a brand-new player id — there's no session resume. See Player presence.
