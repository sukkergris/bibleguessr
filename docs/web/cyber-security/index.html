Cyber security

The edge defenses in front of BibleGuessr — IP blocking, rate limiting, scanner tarpits and TLS — how they are wired together, and which of them are actually active right now.

Where this lives

Everything on this page is nginx (OpenResty) configuration under server-replica/nginx. None of it is application code: the F# backend and the Lit frontend are unaware of it. It is a reverse proxy sitting in front of both.

How the config loads

This matters before anything else, because a defense that is not loaded is not a defense. conf.d/*.conf is loaded on two different paths:

  1. Our own nginx.conf, when OpenResty is started with -c /etc/nginx/nginx.conf.
  2. The OpenResty image's built-in default config, which does include /etc/nginx/conf.d/*.conf and nothing else of ours — this is what runs if the -c argument is missing from the container's command.

Global definitions ($bad_guys, the api_limit zone, log formats, upstreams) are therefore included from conf.d/00-globals.conf, which sorts first in that glob, rather than from nginx.conf. Hanging them off the first file in conf.d/ keeps them defined on both paths.

Getting this wrong fails loudly and immediately — nginx refuses to start with unknown log format "realip" or unknown "bad_guys" variable — so a misconfiguration here is an outage, not a silent hole. Do not re-include includes/http-globals.conf from nginx.conf: defining the same geo/map/log_format twice is itself a startup error.

Layer 1 — Catch-all servers

conf.d/00-globals.conf defines default_server blocks on both 80 and 443 that return 444. Port scanners and SNI probes that connect by IP address, or with an unrecognized Host, get nginx's non-standard 444: the connection is closed with no response at all. Only requests whose Host matches a real server_name reach the application.

The 443 catch-all needs a certificate to exist at all, so it uses a self-signed dummy pair from ssl/. It is never presented to a legitimate visitor.

Layer 2 — IP blocklist

includes/bad-ip-entries.conf holds the address list — bare address value; entries with no surrounding block — currently 23 IPs, each annotated with why it was added (systematic scanners, WordPress vulnerability probes, high-volume offenders).

Two geo blocks include that one list, so the addresses are maintained in a single place: $bad_guys in includes/bad-guys.conf, and $is_bad_ip in includes/geo-bad-ips.conf. Each block sets its own default 0;, which is why the shared file must not contain one.

Why the list is split out

A geo block cannot include another geo block — nginx rejects it with unexpected "{". Including bad-guys.conf from inside geo $is_bad_ip { … } was exactly that mistake, and it only went unnoticed because nothing included the file. Include bad-ip-entries.conf, never bad-guys.conf, from inside a geo block.

$bad_guys is consumed in conf.d/10-bibleguessr.conf and in includes/security-checks.conf (return 444). $is_bad_ip is defined and correct but is not yet read anywhere — it exists for a second consumer that has not been written.

Layer 3 — Rate limiting

includes/rate-limiting.conf defines one zone: 

limit_req_zone $http_cf_connecting_ip zone=api_limit:10m rate=10r/s;

It is applied to /api/ only, with burst=20 nodelay and limit_req_status 429. Static assets and the frontend are not rate limited.

The key is a client-supplied header

The zone keys on $http_cf_connecting_ip, not $remote_addr. That is correct behind Cloudflare, which overwrites the header. Reached directly, the header is attacker-controlled: a different value per request means every request gets its own bucket and the limit does not bind. The same applies to the realip access-log format, which logs that header as the client address. This is safe only as long as the origin is not reachable except through Cloudflare.

Layer 4 — Tarpits and decoys

includes/tarpit.conf matches paths that only a scanner would request — dotfiles and secrets (.env, .git, aws/credentials), any .php URL, known CMS admin paths (wp-login.php, phpMyAdmin, joomla), and DNS-over-HTTP paths (dns-query) used to probe for open resolvers.

Rather than a fast 403, each match is answered by a Lua handler (lua/tarpit.lua) that generates a fake configuration file and streams it slowly — 10 KB/s for generic probes, 8 KB/s for PHP, 4 KB/s for CMS admin paths — with a Content-Disposition header naming it production.conf. The scanner's connection is held open on a worthless file instead of being freed for the next target.

Nothing is read from disk: there is no decoy file to mount, build into the image, or commit. The body is open-ended, so the response is chunked with no Content-Length, and the bait values are randomized per request — two scanners never receive byte-identical bodies.

Why the pacing is in Lua

limit_rate only throttles nginx's own file and proxy output filters; it does not apply to ngx.print from a content_by_lua handler. The handler therefore paces itself against elapsed wall-clock time, sleeping only while it is ahead of the budget the configured rate allows. Per-block sleeps were tried first and drifted well above the target, because blocks vary in size and ngx.sleep has millisecond granularity.

Two safeguards keep a tarpit from costing more than it saves: ngx.on_abort plus a checked ngx.flush stop generation the moment the scanner hangs up, and max_seconds (default 900) caps how long any single connection is held. Because the handler sleeps rather than spins, a held connection costs a coroutine, not a worker.

Ordering matters in includes/tarpit.conf: nginx uses the first matching regex location, so the specific CMS admin list is placed above the generic \.php$ rule. Reversed, every .php path would take the faster generic rate.

Hits are logged under the security_events format (includes/log-formats.conf), which prefixes each line with SECURITY_EVENT: and records both $remote_addr and the Cloudflare header, so tarpit traffic can be grepped out of the normal access log.

Layer 5 — Sensitive-path blocking

includes/security-headers.conf covers a similar path list to the tarpit, adding node_modules, with access_log off so routine scanner noise does not fill the log. It uses the same generated body, so it too needs no file on disk. Despite the filename it defines no HTTP security headers — see the gaps below.

Layer 6 — TLS

includes/ssl-params.conf is applied to the main HTTPS server. TLS 1.2 and 1.3 only, an explicit forward-secrecy cipher list (ECDHE/DHE with AES-GCM or ChaCha20-Poly1305), ssl_prefer_server_ciphers off so the client's order wins, a 1-day 10 MB shared session cache, and ssl_session_tickets off to protect forward secrecy. Port 80 redirects to HTTPS with a 301, apart from the ACME challenge path used for certificate renewal.

Verifying a change

Because the config loads on two paths, a config test should cover both. In a throwaway container with the config copied to /etc/nginx: 

openresty -t                              # image default config path
openresty -c /etc/nginx/nginx.conf -t     # our config path

Both must report test is successful. To check that a geo variable actually resolves — a syntax pass does not prove this — send requests with a spoofed X-Forwarded-For to a probe server that has real_ip_header X-Forwarded-For set and returns $bad_guys / $is_bad_ip, and confirm a known-bad address yields 1 while a clean address yields 0.

Known gaps

  • No HTTP security headers. Nothing sets Strict-Transport-Security, Content-Security-Policy, X-Content-Type-Options, Referrer-Policy or X-Frame-Options — despite security-headers.conf being named for it.
  • Rate limiting trusts a client header. Safe behind Cloudflare, ineffective if the origin is reachable directly. Nothing currently enforces that it is not.
  • The blocklist is manual. 23 hand-collected IPs, updated by editing a file; scanners rotate addresses far faster than that. It is a supplement to Cloudflare, not a substitute.
  • $is_bad_ip has no consumer. Defined and verified, but unused.
  • The old decoy file is still in git. The tarpit no longer reads it, but the-forbidden-zone/production.conf (100 MB of random bytes) is still tracked — the bulk of the repository's ~129 MB history, paid by every clone. It can now be deleted; purging it from past history needs a rewrite.

Implementation

server-replica/nginx/nginx.conf is the entry point; conf.d/00-globals.conf loads the globals and the catch-all servers; conf.d/10-bibleguessr.conf is the site itself. The defenses are in includes/: bad-ip-entries.conf, bad-guys.conf, geo-bad-ips.conf, rate-limiting.conf, tarpit.conf, security-checks.conf, security-headers.conf, ssl-params.conf and log-formats.conf. The generated tarpit body is lua/tarpit.lua, found via the lua_package_path set in includes/http-globals.conf.
