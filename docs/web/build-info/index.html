Feature

Build info

The API image carries the commit it was built from, where it was built and its image tag. The API serves them at /api/build-info, and the nerd panel shows them, so a running server says exactly which build it is.

The three values

VariableNerd panel rowSet by
BUILD_SHA Commit The workflows (github.sha); a local build passes it by hand.
BUILD_CONTEXT Build context The BUILD_CONTEXT workflow variable; locally the gitignored .github/workflows/.vars or the shell — see Multi-platform images.
IMAGE_TAG Image tag Task (Taskfile.Docker.yml): the release version from scripts/ci/load-image-version.sh, or local for a host-only build — see Versioning.

How they get there

  1. build/docker-compose.build.yml passes all three as build args to the API image, in the ${VAR:?} form, so a build without one fails instead of baking in an empty value.
  2. build/Dockerfile.api turns each ARG into an ENV of the same name in the runtime image.
  3. backend/Api/BuildInfo.fs reads them from the environment once at startup. An empty or missing variable becomes null on the wire.
  4. GET /api/build-info answers {"buildSha": "…", "buildContext": "…", "imageTag": "…"}.
  5. The nerd panel (Alt+Shift+N) fetches it once and shows an API image section: Not set for a null value, Unavailable with the error if the request fails. A full commit SHA wraps rather than running out of the panel.
Outside an image

Under task dotnet:dev the API reports whatever its process inherited, not a build: the commit is Not set, the devcontainer sets BUILD_CONTEXT=debian-devcontainer, and Task exports IMAGE_TAG to every task from Taskfile.Docker.yml, so the image tag shows the release version in the working tree.

These are the API image's values. The nginx image gets BUILD_SHA and BUILD_CONTEXT too, written to build-sha.txt and build-context.txt next to the frontend; the nerd panel doesn't read those.

Tests

  • backend/Tests/BuildInfoTests.fs — reading the variables, unset and empty values, trimming, and the JSON shape the frontend expects.
  • frontend/src/components/build-info.test.ts — the text each row shows while loading, once loaded, for a null value and after a failure.
  • frontend/e2e/nerd-panel-build-info.spec.ts — the section with a mocked endpoint: the values, Not set, Unavailable, and a full SHA wrapping.

To check a real image: build it with task docker:build:api (with DOCKER_USERNAME, BUILD_SHA and BUILD_CONTEXT set), run it, and request /api/build-info from inside the container (docker exec <container> wget -qO- http://127.0.0.1:8080/api/build-info).
